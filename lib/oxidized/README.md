# Oxidized 核心模块

这是 Oxidized 的核心模块目录，包含了网络设备配置备份系统的主要组件。

## 目录结构

### 核心文件
- `cli.rb` - 命令行接口模块，处理启动参数和进程管理
- `core.rb` - 核心模块，负责系统初始化和主循环
- `config.rb` - 配置管理模块，处理所有配置选项
- `version.rb` - 版本管理模块

### 任务和线程管理
- `job.rb` - 单个任务类，继承自Thread
- `jobs.rb` - 任务队列管理类
- `worker.rb` - 工作器类，管理线程池和任务调度

### 节点管理
- `node.rb` - 单个网络设备节点类
- `nodes.rb` - 节点集合管理类
- `node/` - 节点相关子模块

### 系统组件
- `manager.rb` - 模块管理器，负责动态加载各种模块
- `logger.rb` - 日志系统模块
- `signals.rb` - Unix信号处理模块

### 子目录
- `config/` - 配置相关子模块
- `input/` - 输入方法模块（SSH、Telnet等）
- `output/` - 输出方法模块（文件、Git等）
- `source/` - 数据源模块（CSV、SQL等）
- `model/` - 设备模型模块（各种网络设备）
- `hook/` - 钩子模块（事件处理）

## 核心架构

Oxidized 采用模块化架构，主要组件包括：

1. **CLI模块** - 处理命令行参数和进程管理
2. **Core模块** - 系统核心，协调各个组件
3. **Worker模块** - 管理工作线程池
4. **Node模块** - 表示和管理网络设备
5. **Manager模块** - 动态加载各种功能模块

## 工作流程

1. CLI模块解析命令行参数
2. Core模块初始化系统组件
3. Manager模块加载各种功能模块
4. Worker模块启动工作线程池
5. 从Source模块获取设备列表
6. 使用Input模块连接设备
7. 使用Model模块解析设备配置
8. 使用Output模块保存配置
9. 通过Hook模块处理事件

## 扩展性

系统设计为高度可扩展，支持：
- 自定义输入方法
- 自定义输出方法
- 自定义数据源
- 自定义设备模型
- 自定义事件钩子
